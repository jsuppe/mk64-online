MK64 ONLINE / CONTROLLER FIELD GUIDE

From title screen to starting grid.

Every added online menu, the host/guest handoff, and what each button actually does. Fresh captures from the v77 product ROM — not menu mockups.

HOST: 1P → ONLINE → HOST GAME → class/Battle → visibility → lobby → START → driver → map → ready → race.

JOIN: 1P → ONLINE → JOIN GAME or FIND GAME → lobby → host starts → driver → wait for host’s map → ready → race.

MENU WALKTHROUGH / v77

01 / Get to ONLINE

  1. At the title screen, check the yellow JSUPPE VERSION 77 stamp. Everyone should use the same ROM build.
  2. Press START. Pick 1P GAME and confirm with A.
  3. Move down to ONLINE, press A, then confirm the OK? prompt with A.

One local controller per console/emulator. ONLINE is a 1P mode: the other seats come from the network, not the local split-screen selector. You don’t choose engine class here; the host does that later.

Button names below are N64 controller buttons. Bind them in your NetPak64-enabled emulator; these are not PC keyboard shortcuts.

MENU WALKTHROUGH / v77

02 / Pick your route

Use the stick or D-pad ↑/↓ to highlight a row. A opens it; B returns to the game’s main menu.

  • HOST GAME — create a room and choose its rules.
  • JOIN GAME — enter a friend’s six-character room code.
  • FIND GAME — browse public rooms on your relay.
  • NAME — edit the name shown to other players.

Read the signal bars

Blinking red: connecting to the relay. Two green bars: relay connected, not seated in a room. Three green bars: relay connected and in a room. HOST/FIND need the relay link; code entry can open before the link is ready, but joining still needs it.

MENU WALKTHROUGH / v77

03 / Set your player name

Select NAME and press A.

  • ←/→: move between eight character slots.
  • ↑/↓: cycle the selected character.
  • A: save; B: discard edits and return.

Available characters: space, A–Z, 0–9, hyphen and period. Trailing spaces are trimmed. An all-blank name will not save. The emulator/device handles identity persistence; saving updates the room identity too.

MENU WALKTHROUGH / v77

04 / Host: class, then visibility

Choose HOST GAME → A.

SELECT CLASS

↑/← cycle backward; ↓/→ cycle forward through 50CC / 100CC / 150CC / BATTLE. A continues; B returns to ONLINE. 100cc is the default cursor.

GAME VISIBILITY

↑ or ↓ toggles PRIVATE — CODE ONLY / PUBLIC — LISTED. A creates the room; B returns to class selection. PUBLIC is the default.

Public rooms appear in FIND GAME on the same relay. Private rooms are joined by code. Class/mode belongs to the host; joiners adopt it. Battle’s arena is selected after character selection, not here.

Developer launch override: NP64_ROOM uses join-or-create for that exact code instead of the normal random-room creation path. The visibility picker does not set creation flags on that override path.

MENU WALKTHROUGH / v77

05 / Join by room code

Ask the host for the code shown in their lobby. Select JOIN GAME → A.

  • ←/→: select one of six positions.
  • ↑/↓: cycle that position’s letter/number.
  • A: join as a racer.
  • Hold Z while pressing A: join as a spectator.
  • B: return without joining.

The code alphabet excludes 0/O and 1/I. A launch code may pre-fill the editor, but you still confirm it.

Unexpected host lobby? This implementation joins or creates the code. If the room does not exist, you become its host instead of waiting for someone who isn’t there. Check the code and the relay with your friend. You cannot spectate a room you just created.

MENU WALKTHROUGH / v77

06 / Find a public game

Select FIND GAME → A. The browser requests a list from your connected relay.

  • ↑/↓: highlight a listed room.
  • A: join it as a racer.
  • Hold Z + press A: watch instead.
  • R: refresh the list. B: back.

Rows show a room code, player-count field and host name. Confirm attendance in the lobby roster rather than treating the browser count as a ready-player check. NO PUBLIC GAMES is a valid empty list, not necessarily a failed connection. Private rooms won’t appear here. If a room vanishes between listing and joining, join-or-create can put you in a host lobby.

MENU WALKTHROUGH / v77

07 / Lobby: host vs. guest

Host view

Share the room code. Wait until your friends appear in PLAYERS, then press START to begin character selection for the room. B leaves the room and returns to ONLINE. The class/Battle label shows your selected rules.

Guest view

Check the room code and roster. WAITING FOR HOST is expected: guests cannot start a product-build session. B cancels your membership and returns to ONLINE.

The roster displays peer round-trip ping in milliseconds: green below 60 ms, yellow below 120 ms, red above that. Missing ping means it has not been measured yet. Watchers are marked in blue; the local watcher name gains a W.

The lobby renders only five peer rows plus your own name. Do not use that visible row count as a full-room capacity readout. If the host leaves before START, guests return to ONLINE after the host-loss check.

MENU WALKTHROUGH / v77

08 / Choose your driver

After the host presses START, every player reaches the familiar PLAYER SELECT screen.

  • Stick/D-pad: move around the character grid.
  • A: lock your character.
  • A again at OK?: move to map selection.
  • B at the OK prompt: return to character selection.

The character choice is synchronized before launch because different characters have different physics. A watcher still passes through this flow, but their character pick is not used as a live driver.

MENU WALKTHROUGH / v77

09 / Only the host picks the map

Host: race course

Use ←/→ to select a cup, then A. Use ↑/↓ to select a course, then A to lock it. The room adopts that course and advances through the ready handshake.

Host: Battle arena

When BATTLE was chosen, use ↑/↓ on the stock Battle map selector, then A to confirm the arena. The four arenas are Big Donut, Block Fort, Double Deck and Skyscraper.

Guest: WAITING FOR HOST

You do not choose a separate course. The black WAITING FOR HOST / CHOOSING COURSE panel remains until the host’s selection arrives. Guest map inputs are swallowed; it advances automatically once the course is known.

Online start locks the map flow: host B is swallowed too. Do not expect the offline map screen’s normal back-out behavior once the room has started.

MENU WALKTHROUGH / v77

10 / WAITING FOR ALL PLAYERS

The second black panel means the chosen course is known, but the ready/go handshake is still completing. It is not another menu you must confirm.

The host waits for peers’ ready messages and sends GO; guests launch on GO. Let every player finish character selection. If it persists, check that everyone is still connected and running the same ROM version.

The source has an approximately 30-second barrier timeout and departure handling; these are fallback paths, not evidence that a missing player is ready. VERSION MISMATCH / UPDATE ROMS is a warning to get the room onto one build, not a normal step to ignore.

MENU WALKTHROUGH / v77

11 / START is a local menu, not a race pause

During an online race, press START to open CONTINUE / QUIT RACE.

  • D-pad ↑/↓: switch between the two options.
  • A: confirm the selected option.
  • B or START: close the menu and continue.

The race keeps running. Despite the panel’s “PAUSED” heading, this is a local overlay. Your driving input becomes neutral while it is open, so your kart coasts; other players are not paused.

QUIT RACE announces your departure, then leaves the session and returns you to the title/menu flow. Other peers convert your kart to CPU control rather than waiting indefinitely for your inputs. Spectators can quit too; a tape replay has no live membership to quit.

MENU WALKTHROUGH / v77

12 / Watcher and replay camera controls

Join an existing room with Z held while confirming A in code entry or FIND GAME. You occupy a watcher slot rather than sending racing inputs; the room simulates a CPU in that slot.

  • R: next kart. L: previous kart.
  • C →: normal chase view.
  • C ↓: Lakitu rear view.
  • C ↑: front-facing view.
  • C ←: cinematic path view.

These are spectator/replay viewer controls, not a normal racer camera feature. If you want the demo to look like playing MK64, use the normal chase view rather than cinematic.

Camera bindings are checked against v77 source. This page’s screenshots cover menu navigation and a two-peer product-ROM start/quit session; they do not constitute a spectator/replay runtime qualification. Tape loading is a separate emulator/developer workflow, not a new ROM menu documented here.
